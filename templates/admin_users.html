Adds a “Sign in” link to the public page. Passwords are checked against Jellyfin itself on every sign-in and are never stored here. Leave this off unless you want a login form on your status page — if the portal is reachable from the internet, turning this on publishes a Jellyfin login form to the internet.
The server URL and API key come from that Integration — there's deliberately no second copy of them here, so there's only ever one answer to “where is your Jellyfin”. Only matters if you have more than one.
Only has any effect while sign-in is enabled above — with it off, the report form stays open to everyone exactly as before. Worth thinking about: if Jellyfin is down, nobody who hasn't already signed in can sign in, so nobody new can report the outage. Turn this off if you'd rather take the spam risk than lose reports during an outage.
Separate from your admin session timeout, and deliberately much longer by default — a visitor signing in to file a report isn't holding privileged access. Set to 0 for no idle timeout.

Cached Jellyfin users

A local copy of Jellyfin's user list, refreshed on a schedule. It is never used to check a password — sign-in always asks Jellyfin live. Its jobs are to keep people who are already signed in from being thrown out while Jellyfin is unreachable, to revoke the session of anyone removed or disabled in Jellyfin, and to hold your own per-user decision below.

Everyone is allowed by default. Blocking someone here stops them signing in to this portal and ends the session they're currently in, on their next page load — it does nothing to their Jellyfin account. The block is remembered across syncs, so it survives the user list being refreshed. To take away their Jellyfin access instead, disable them in Jellyfin: the next sync picks that up on its own. {% if blocked_count %}
